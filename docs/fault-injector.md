# Fault injector

The server's `EpisodeRegistry` wraps every episode's `MockApp` in a `FaultInjector` (`src/toolharness/injector/injector.py`). The injector passes calls through and corrupts at most one response per episode.

## How a fault fires
- **When:** on the first `get_article` call that returns an **answer page**, i.e. a page holding a supporting-fact sentence (`MockApp.answer_pages()`). Title case doesn't matter. `search` is never corrupted.
- **Once:** faults are transient. Every later call, including an identical retry, gets clean data, so the agent can recover by retrying or cross-checking.
- **Maybe never:** if the agent never fetches an answer page, nothing is injected. `summarize_gt` reports `fault_injected=False`, and detection metrics skip that episode.
- **Same corruption everywhere:** the random generator is seeded by `(X-Fault-Seed, scenario_id)`, not the episode. Every model and condition sees the exact same corrupted text.

## Ground-truth log
The server's `--gt-log` file gets one JSON row per agent tool call:

| Field | Meaning |
|---|---|
| `episode_id`, `scenario_id`, `fault_type` | which episode |
| `call_index`, `tool`, `args` | which call (0-based, in order) |
| `corrupted` | `true` on the one corrupted call |
| `retry_of_corrupted` | `true` when the agent re-fetched the corrupted page |
| `original`, `corrupted_text`, `corrupted_is_error` | clean vs. returned response, **only on the corrupted row** (else `null`) |

`summarize_gt(path)` (`src/toolharness/injector/ground_truth.py`) gives per-episode `fault_injected`, `injected_at_call` and `retries_of_corrupted`. The agent and the proxy must never read this file.

## Adding a fault type (#9–#13)
1. Create `src/toolharness/injector/faults/<fault>.py` with a `Corruptor` subclass (`src/toolharness/injector/corruptors.py`) that implements:
   ```python
   def corrupt(self, call, clean, history, rng, target) -> ToolResponse:
   ```
   - `clean.text`: the clean JSON (`ArticlePage`: title, page, total_pages, sentences, last_updated, source_id)
   - `target`: an `AnswerTarget` with `title`, `page`, `sentence_positions` (indexes into `sentences` that hold supporting facts) and `gold_answer`
   - `history`: earlier `CallRecord`s in this episode (each with `.clean` and `.returned`)
   - `rng`: use it for **every** random choice; never use the global `random` module
2. Register it in `src/toolharness/injector/faults/__init__.py`: one import and one `FaultType.X: YourCorruptor()` entry. Until a fault type is registered, the server rejects its scenarios.
3. Override `should_trigger(call, clean, history, target)` only if the default rule doesn't fit. The default fires when `target` is set, i.e. on an answer page. `silently_wrong` overrides it to pass over skipped pages, and contradiction will need an earlier fact to contradict.
4. Add `tests/test_fault_<fault>.py`: corrupt an answer page from `data/sample/hotpotqa_sample.jsonl` and check the properties below.

| Fault | Return | Must hold |
|---|---|---|
| `hard_failure` | `ToolResponse(text=<realistic error message>, is_error=True)` | message looks like a real API failure (timeout, 500, rate limit) |
| `malformed` | `is_error=False`, broken payload | fails `ArticlePage.model_validate_json` (invalid JSON, missing field, wrong type, or truncated) |
| `silently_wrong` | valid `ArticlePage` JSON | a fact in a `target.sentence_positions` sentence changed, so `target.gold_answer` no longer follows |
| `stale` | valid `ArticlePage` JSON | `last_updated` clearly older than `AS_OF − CLEAN_DATE_WINDOW_DAYS`, plus an outdated fact |
| `contradiction` | valid `ArticlePage` JSON | conflicts with a fact the agent already received earlier in `history` |

## Implemented faults
| Fault | File | What the agent gets |
|---|---|---|
| `hard_failure` (#9) | `faults/hard_failure.py` | `isError: true` with one of five API errors (500, 502, 503, 504, 429). No simulated delay: the server's tools share one event loop, so sleeping would stall every episode. |
| `malformed` (#10) | `faults/malformed.py` | A normal (non-error) result in one of four variants: an HTML error page, `sentences` missing, `sentences` replaced by a count, or the response cut off partway into the first supporting sentence, before the answer. No variant keeps a full supporting sentence, so the agent has to re-fetch to answer from this page. |
| `silently_wrong` (#11) | `faults/silently_wrong.py` | A valid page where one fact the question depends on is swapped for a plausible wrong one (e.g. "Billie Holiday's screen debut" → "Ella Fitzgerald's screen debut"). Every exact mention on that page is swapped; the title is not. The swaps are pre-generated by an LLM (below). |

## Fact edits for `silently_wrong`
Each silently_wrong answer page needs a **fact edit**: an exact span from a supporting sentence (`original_value`), a plausible replacement (`new_value`), and the answer a reader who trusts the edited page would give (`new_answer`). Claude Sonnet 5.5 writes them once, through OpenRouter. It isn't one of the four models under test.

```bash
python -m toolharness.data.fact_edits --scenarios data/scenarios/hotpotqa.jsonl --out data/edits/hotpotqa.jsonl
python -m toolharness.data.fact_edits --scenarios data/scenarios/longseal.jsonl --out data/edits/longseal.jsonl
python -m toolharness.mcp_server --scenarios data/scenarios/*.jsonl --edits data/edits/hotpotqa.jsonl data/edits/longseal.jsonl
```
- **Checks:** a reply is rejected (and retried up to 3 times with the reason) if its JSON is broken, its span isn't copied exactly from a supporting sentence, or it reuses the correct answer.
- **Resumable:** existing edits in `--out` are kept, so rerunning only asks for missing pages. A page that still fails is listed, and the command exits with code 1.
- **Human review:** after generating, read the edits and list weak ones in a review file (`data/edits/<dataset>_review.jsonl`, one `{"scenario_id", "title", "page", "action", "note"}` per line). Then rerun with `--review <file>`.
  - `"redo"` regenerates that page's edit, with the note added to the prompt. The note should say what's wrong, never what to write, so the edit is still written by the edit model. Sonnet may reply that nothing on the page can change the answer, which marks the page skipped.
  - `"skip"` marks a page whose facts don't affect the answer (e.g. one that only mentions it in passing). The fault doesn't fire there; it fires on the first answer page the agent opens that has a real edit. If every answer page of a scenario is skipped, that scenario never gets a fault.
- **Committed:** HotpotQA edits (`data/edits/hotpotqa.jsonl`) are committed so everyone runs on the same edits. LongSeal edits quote benchmark text, so they're gitignored.
- **Server:** without `--edits`, silently_wrong episodes are rejected. With it, the server refuses to start if any silently_wrong answer page has no edit.
- **Analysis:** `new_answer` tells you when an agent was *fooled*, meaning it gave the planted answer rather than just a wrong one.

**LongSeal note:** a LongSeal scenario records how its supporting sentences were found in `metadata["evidence"]`.
- **`answer_match`:** the target sentences contain `gold_answer`.
- **`fragment`:** the target sentences come from the dataset's highlighted evidence passage, and **may not contain `gold_answer`**. This is common for counting questions ("how many…"). For these, change a number, date or name *in the target sentence* rather than searching it for the answer string.
